# reflection · 八周反思

> 写作说明：这份反思是我（赵熙语）对每一周"我到底学到了什么"的总结。
> 代码与实验过程是在 AI 辅助下完成的，凡是 AI 替我跑出来、我自己还没有亲手重做的操作，
> 我都在条目里标了「待补做」——备考结束后我会逐条补上手，不把"看过"当成"会了"。

## Week01 · 存在

第一次跑起来的时候，我盯着浏览器里那行 `Hello, I am Sylvia. I Exist.` 看了很久。
它什么都没干，但它是**真的在运行**：URL 是被谁接住的、字符串是被谁写进响应体的，
我第一次把"我敲的东西"和"屏幕上出现的东西"之间的那条链路走完了。
`@SpringBootApplication` 不只是个启动开关，它还决定了"从哪里开始扫描"。

## Week02 · 结构化表达

从"返回一句话"到"返回一个对象"，中间隔着一整个 Jackson。
我原先以为返回对象是"高级写法"，敲完才发现区别只有一个：**内容协商**——
String 走文本转换器，对象走 JSON 转换器，浏览器能不能"读懂结构"取决于这一步。
破坏实验里我改了字段名 `owner → author`，值一个字没变，前端立刻取不到东西。
那一刻我明白：**字段名就是 API**，不是内部实现。

## Week03 · 身份

给 `/profile` 填五个字段时我卡了一会儿，因为"我的博客是什么"这个问题
比"怎么返回 JSON"难得多。最后我写的是：
`blogName` 熙语的数字花园、`owner` 赵熙语 Sylvia（25281E127）、
`introduction` 一句自我介绍、`interests` 我真正在学的东西、`vision` 我想让它变成什么。
这一周我第一次意识到，接口里的字段名其实是**我在向世界介绍自己时的措辞**。

## Week04 · 倾听

`POST` + `@RequestBody` 让我第一次做出"能收东西"的接口。
三个 Bug 里有两点我记到现在：
一是 `Content-Type: application/json` 少一个字就是 415，转换器不知道这堆字节是什么；
二是 JSON 键名写错时服务端**照样返回 200**，只是字段是 `null`。
200 只代表"受理了"，不代表"成立"——这句话我后面每一周都在用。

## Week05 · 结构

把 `ArrayList` 从 Controller 里搬出去，换成 Service + Repository 接口，
行为一点没变，我却第一次感觉到"结构"这个东西的价值：
它不改变结果，它改变的是**以后改起来难不难**。
破坏实验里删掉 `@Service`，应用直接在**启动阶段**报错，
而不是等我发请求才崩——依赖在启动时接线，早失败比晚失败幸运。

## Week06 · 记忆

内存版重启就失忆这件事，我是真的被它咬了一次：
重启前有两条留言，重启后列表空了，再提交一条，id 又从 1 开始。
那一刻"进程结束 = 堆消失"从一个概念变成了我屏幕上的现象。
换成 MySQL 之后，我特意做了一次"绕过应用直接往表里插一条"，
应用居然读到了它——这才叫读的是数据库，不是自己的内存。

## Week07 · 发现

分页是我这八周里最容易被骗的地方。
去掉拦截器之后，接口照样返回 200，`items` 照样有数据，只是"忘了切片"。
如果不是去日志里找 `LIMIT`，我大概会以为它是对的。
这一周学到的方法不是"怎么加拦截器"，而是**怎么证明它真的加了**。

## Week08 · 文章与契约

`PUT` 和 `DELETE` 补上了资源的一生：发布、被读、被改、被撤回。
但真正让我印象深的是 404：
注释掉 `@RestControllerAdvice` 之后，"文章不存在"变成了 **500**——
一个"客户端找错了门"的事，被说成"服务器坏了"。
加上 advice 之后，同一个请求变成 `404 + {code:404, message:"article not found"}`。
**失败也是一种回答**，而且必须和成功长得一样，前端才只需要信一次形状。

## 关于 AI 辅助

这八周的代码大量借助了 AI 完成，我不打算假装那是我一个人敲的。
我给自己定的底线是：**AI 跑过的每一步，我要能自己讲出为什么**。
所以我把每一次请求、每一条 SQL、每一个破坏实验的输出都留了证据
（`docs/evidence.md`、`docs/evidence-destructive.md`、`docs/ai-log.md`），
而不是只留一句"做完了"。
